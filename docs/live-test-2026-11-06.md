# Live test, 6 November 2026

**A real swap of 2 USDC on Ethereum delivered 1.997376 USDC on Base, paid for with x402 on Hedera and recorded on Arkiv.** It succeeded on the third agent run. The earlier runs exposed two bugs, both now fixed.

Every result below was checked at its source, not only in Crossfare's own logs: the Hedera mirror node, the HCS topic, Arkiv, Ethereum and Base RPC, and SwapKit's `/track`.

## What went wrong

| # | Problem | When | Effect | Fix |
| --- | --- | --- | --- | --- |
| 1 | Arkiv rejected any lifetime that isn't a multiple of its 2-second block time, so about half of all quotes failed to publish | Second run | The agent found no record and **stopped before sending funds**, as designed. That run still cost 0.01 testnet USDC, because the quote itself had succeeded | [`0cdaacb`](https://github.com/Paulie-Aditya/CrossFare/commit/0cdaacb): round up |
| 2 | Three transaction hashes exceed Arkiv's 128-byte limit on a string, so the final update failed | The real swap, after delivery | The funds were unaffected, but the public record stayed at `executing` and would have expired minutes later | [`776cb4c`](https://github.com/Paulie-Aditya/CrossFare/commit/776cb4c): store as bytes. I repaired this one record by hand through the same code path |
| 3 | Status stayed at `awaiting_deposit` after the transaction was sent, because SwapKit lags a broadcast | The real swap | Misleading for about a minute | [`dbe4d55`](https://github.com/Paulie-Aditya/CrossFare/commit/dbe4d55) |
| 4 | The route's middle hash is on neither chain, and the UI would have linked it to Basescan | Found by reading the real data | A wrong link, never shown live | [`dbe4d55`](https://github.com/Paulie-Aditya/CrossFare/commit/dbe4d55) |

A fifth bug appeared when the developer tried the UI: SwapKit reports all-zero placeholder hashes until a deposit exists. They were stored as real, so the status jumped to `confirming`, and the order page hid its deposit address about 15 seconds after it appeared. [`4bbb359`](https://github.com/Paulie-Aditya/CrossFare/commit/4bbb359) fixed it, and in a later test the order page held for the full 40 seconds observed.

Both Arkiv bugs got past the tests because the fakes don't apply the SDK's limits. Both are in [`arkiv/friction.md`](../arkiv/friction.md).

## Second real swap: no wallet connected

The developer ran this one through the UI with no wallet connected, sending the deposit from their own wallet app.

| Fact | Value |
| --- | --- |
| Sold | 5 USDC on Ethereum |
| Delivered | 0.002225665081008325 ETH on Base, 17 basis points of slippage as reported by SwapKit |
| Route | SwapKit through NEAR |
| Deposit | [`0x360be9f0…dac0`](https://etherscan.io/tx/0x360be9f057f35a6eb11946a996c3c471c311b43184a3466f8a8313543079dac0) |
| Delivery | [`0xeccf951a…0d`](https://basescan.org/tx/0xeccf951a2e396be57c402585e0b5e65f65d03f4329227d5989ae42af9bb2e50d) |
| Arkiv record | [`0x6e560d37…5aa0`](https://rabdi.explorer.arkiv.network/entity/0x6e560d372a560dfd29418ab5a076d86f833cadb20b4f3f3074096abe198a5aa0) |

**The swap worked, but the page didn't show it.** It stayed on "Send your deposit" until the swap finished. Crossfare only asked SwapKit, whose status was checked rarely and which can lag, and the API log also shows connection timeouts to SwapKit during this period. The exact status SwapKit returned mid-swap wasn't recorded, so which of these dominated isn't known.

The fix reads the deposit address on chain every 4 seconds, takes progress from SwapKit's individual legs, and never moves a status backwards. Against a mock API each stage shows correctly. **This hasn't yet run during a real swap**, and the leg values it relies on come from this swap's finished `/track` response.

The two finished swaps' Arkiv records were rewritten by hand afterwards to the new readable status and summary, using the service wallet.

## Not tested live

- **A Uniswap swap on chain:** only its quote ran, with no transaction sent.
- **The UI with a real wallet connected:** the wallet chooser and wallet paths ran only against a mock API with fake wallets.
- **A deposit from an exchange:** SwapKit doesn't document another sender funding a channel.
- **Replaying a real payment:** this is covered by automated tests, not repeated against the facilitator.
- **Late or wrong deposits:** SwapKit's docs don't cover them, and testing would risk funds.
- **A second real swap with the fixes in place:** the Arkiv fixes ran on real data through the repair, and the status fix hasn't seen a real send. The UI test also opened an unused deposit channel, which is harmless if nothing is sent to it.
- **EC2:** nothing has run on a server yet.

## Reproduce it

```sh
pnpm --filter @crossfare/api start
AGENT_ALLOW_LIVE_SWAPS=true pnpm --filter @crossfare/agent start \
  --from eth:usdc --to base:usdc --amount 2 --recipient <your Base address>
```

This spends real funds. Without `AGENT_ALLOW_LIVE_SWAPS=true`, the agent pays for a quote and stops before sending anything.
